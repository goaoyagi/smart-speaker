実装前に決着が必要な相違点
  1. num_ctx を 8192 にするか 4096 にするか：3案が 8192、Kimi のみ 4096。Pi 5（8GB）でモデル本体と作業領域を取り合うため、モデル選定（表3最下部）とセットで決める必要がある。
  2. temperature 0.3 か 0.7 か：Ultra だけが 0.7。「検索結果を事実として扱う」用途では低め（0.2〜0.3）が3案の多数意見。
  3. num_predict 未指定が「回答が短い」原因か：Fable・Fusion・Ultra は原因の一つと見なすが、Kimi は既定 -1（無制限）だと明言して否定し、原因をプロンプトと材料の薄さに寄せている。実機で /api/show を確認すれば決着する論点。
  4. 推敲パスを入れるか：Ultra・Fusion は「同一検索コンテキスト内の自己精緻化」として提案、Kimi は AGENTS.md の生成後検証禁止に抵触しうるとして不採用。Fable は生成前の Map-Reduce に置き換えて回避。

4案を統合した場合の実装順序（参考）

4案の合議点と、固有提案のうち順序に組み込む価値があるものを統合した案。AGENTS.md の「1 PR ＝ 1目的」に沿って1行＝1 PR の粒度にしている。

順序 内容 根拠となる案 依存追加 備考
1 brain.py に options（num_ctx／num_predict／temperature／repeat_penalty）と system を追加し、config.py＋.env.example 経由で設定化 4案一致 なし 最小変更で最大効果。temperature は多数意見の 0.3 を初期値に。
2 composer.py のプロンプト強化（回答長 3〜5文・結論→補足・指示語は履歴参照・無関係な検索結果は無視可） 4案一致（Kimi は独立ステップ化） なし 1と同一 PR にまとめてもよいが、効果の切り分けには分離が有利。
3 /api/chat 移行と履歴の messages 化（as_messages() 追加）、履歴 turns/clip の拡張、prompt[:10000] をトークン予算管理に置換 Fable・Fusion・Ultra（Kimi は後ろ倒し） なし Kimi の慎重論を採るなら1〜2の効果測定後に着手。

6 本文取得（trafilatura、並列・タイムアウト付き・失敗はスニペットへフォールバック）＋パッセージ再ランク＋RERANK_MIN_SCORE 4案一致（閾値は Fusion のみ） trafilatura 「回答が短い」の材料不足への本命対策。http_client.py に HTML 取得を追加。
